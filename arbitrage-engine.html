Sports Betting & Arbitrage Engine

A sports betting engine designed to allow for live arbitrage detection and almost immediate trade execution.

Overview

This project started as a hobby when I was working on engineering trading platforms at JP Morgan Chase. I implemented arbitrage detection and live execution for five United States based bookies. In September of 2025 I moved to the United Kingdom to pursue my MSc degree, which led me to add two UK bookies with a third one currently in progress. Moneyline markets are currently supported for all bookies with the goal of adding more markets as this platform grows.

How it's designed

The engine is built from four components: Reference Data builds a database of competition and sport ids for each bookie, the Connector streams live odds and watches for arbitrage opportunities, the Arbitrage Trader handles execution logic, and the front-end is the user interface. Curretly, Process Manager 2 (PM2) is used to start and monitor this application.

Front-end UI

  • ReactJS
  • Protobuf

A single-page React app where the user chooses which competitions to track and watches live odds and arbitrage alerts update. It holds a persistent WebSocket open to the Connector — sending subscribe / unsubscribe requests and receiving streaming odds, arbitrage flags, and disconnect notices when a market drops. The websocket messages use Protobuf to keep latency at a minimum.

Reference Data

  • Java
  • Maven
  • Spring Boot
  • SQL

Queries each supported bookmaker's APIs for their sport and competition identifiers and combines everything into a single H2 database the rest of the system maps against. Because many of these sites use anti-bot protection, it uses impersonator to spoof genuine browser TLS fingerprints and slip past modern detection algorithms.

Connector

  • Java
  • Maven
  • Spring Boot
  • Protobuf

This is where most of the logic lives. The connector opens WebSocket connections to each bookmaker to stream live odds for the subscribed competitions, forwards that data to the front-end, and writes the latest prices into an internal data structure that flags arbitrage opportunities the instant they appear.

Arbitrage Trader

  • Python
  • CDP

A Python API for logging in, placing bets, and checking balances across the supported platforms through simple calls. To avoid bot detection at login it uses zendriver which drives automated Chrome sessions using the Chrome DevTools Protocol (CDP). The authenticated sessions are then persisted allowing bets requests to be sent directly to each platform's API via curl_cffi, Python's TLS fingerprint impersonator — keeping execution fast when an arbitrage window opens.
